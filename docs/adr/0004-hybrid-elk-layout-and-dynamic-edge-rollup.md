# 0004: ELK.js＋手動オフセット保存のハイブリッドレイアウトと動的エッジロールアップ

- **Status**: Accepted
- **Date**: 2026-11-26

## Context

Structurizr DSL の `model` には座標情報が存在しないため、自動レイアウトが不可欠である。しかし以下の 2 つの課題が同時に存在する：

1. **空間記憶（Spatial Memory）と手間の両立**: 毎回ゼロから手動配置するのは苦痛だが、完全自動配置のみだと DSL を微修正した際やユーザー独自の地理的配置イメージ（「認証は左上」「決済は右下」）を保持できない。
2. **エッジのスパゲッティ化**: 1 枚の地図に L1〜L3 の全関係線を同時描画すると線だらけになり読めなくなる。また、`big-bank-plc.dsl` のように親レベル（`customer -> internetBankingSystem`）と子レベル（`customer -> webApplication` 等）の両方にエッジが書かれているケースも実在する。

## Decision

1. **ハイブリッドレイアウトを採用する**。
   - 初回・標準配置は **`elkjs`**（階層複合グラフ `INCLUDE_CHILDREN` + `layered`）で決定的に自動計算する。
   - ユーザーが配置調整モード（または `Alt + ドラッグ`）で移動したノードは、絶対座標ではなく **自動レイアウト位置からの相対オフセット差分 (`Record<ElementId, { dx, dy }>`)** として `localStorage` に保存し、非破壊に適用する（個別/全体リセット可能）。
2. **画面上の展開状態に基づく「動的エッジロールアップ（Effective Visible Anchor 射影）」を採用する**。
   - 各ノードの `detailAlpha` に応じて、現在見えている最深の可視祖先ノード `anchor(u)` へすべての元エッジを動的に射影する。
   - 閉じた親内部の自己ループ（`anchor(s) === anchor(t)`）は隠し、同一有向ペア `(A, B)` へ射影された複数エッジ（親直接エッジと子ロールアップエッジの重複を含む）は 1 本の `DisplayEdge`（件数・プロトコル要約付き）へ集約する。
   - 双方向エッジ `(A, B)` / `(B, A)` はベジェ曲線の法線オフセットで視覚的に分離する。

## Alternatives Considered

- **完全自動レイアウトのみ**: 実装は単純だが、ユーザーが好みの地図配置へ微調整できず空間記憶の体験が弱まるため不採用。
- **力学モデル（Force-directed）による有機的配置**: 階層入れ子と直交・階層的データフローの視認性が落ち、再計算ごとの安定性も低いため不採用。
- **定義レベル別の固定フェード切替（ロールアップなし）**: L3 にしかエッジを書いていない DSL だと L1 俯瞰で線が 1 本も見えなくなってしまうため不採用。

## Consequences

- **メリット**:
  - どの粒度でエッジを書いても、引きでは幹線・寄りでは詳細線として自然に見える。
  - 左のシステムだけ L3 展開し、右のシステムは L1 のまま閉じた状態でも、`Container -> System` のように不自然さなく接続される。
- **トレードオフ・注意点**:
  - 手動ドラッグで子要素を親枠外へ動かした場合は親のバウンディングボックスを自動拡張する処理が必要。
  - エッジロールアップはズーム変化時にのみ再計算されるよう、展開状態ハッシュでメモ化してパン操作中の不要な計算を避ける。
