# 0001: 連続セマンティック・ズーム特化＆エディタ非搭載（探索ビューア集中）

- **Status**: Accepted
- **Date**: 2026-11-26

## Context

既存の C4 モデルツール（Structurizr UI / LikeC4 等）は、System Context 図・Container 図・Component 図を独立したビューとして生成し、要素のダブルクリックで別ビューへページ遷移する体験を基本としている。
これに対し c4-zoom では、「Google Maps や Apple Maps のように 1 枚の連続空間を移動・ズームイン・ズームアウトしながらアーキテクチャを自由に見てまわれる体験」を最大の差別化価値として実現したい。

また初期検討段階ではアプリ内にライブ DSL エディタを含める案もあったが、エディタ実装・シンタックスハイライト・編集体験の作り込みに工数が分散すると、本命である「地図としての探索体験」の磨き込みが薄まる懸念があった。

## Decision

1. **空間モデルとして「連続セマンティック・ズーム（空間入れ子 + LOD）」を採用する**。
   - `System ⊃ Container ⊃ Component` を 1 枚の連続 2D 空間へ入れ子配置し、画面占有サイズ（px）に応じた滑らかな LOD 遷移で詳細度を切り替える。
2. **プロダクトのスコープを「純粋な探索ビューア」に絞り、アプリ内での DSL エディタ機能はスコープ外とする**。
   - 入力は内蔵サンプルプリセットの切替、および `.dsl` ファイルのドラッグ＆ドロップ／ファイル選択読み込みとする（DSL 編集はユーザーが普段使う IDE / エディタで行う前提）。

## Alternatives Considered

- **階層ダイブ型（個別ビュー間のアニメーション遷移）**:
  - 各階層のレイアウトを独立させられる利点はあるが、隣のシステムの中身へ横パンして比較する「地図の一体感」が弱く、既存ツール（Structurizr / LikeC4）との差別化が薄れるため不採用。
- **ビジュアル作図エディタ型（IcePanel / Figma 風）**:
  - 作図 UI の複雑性が膨大になり、Architecture as Code（テキスト定義）の利点も失われるため不採用。
- **CodeMirror 6 / Monaco によるライブ DSL エディタ同梱**:
  - バンドルサイズや UI 画面占有・編集系バグ対応が増えるため、探索ビューア体験の完成度を優先しスコープ外とした。

## Consequences

- **メリット**:
  - 画面 100% を地図キャンバスとして使える洗練されたフローティング UI に集中できる。
  - エディタ依存パッケージが不要になり、バンドルサイズ・保守コストが大幅に下がる。
- **トレードオフ・今後の拡張余地**:
  - ブラウザ単体でちょっとした DSL 修正を試すには外部エディタ＋再読込が必要になる。
  - 将来的に開発時のリロード手間を減らしたい場合は、コアエンジンを再利用したローカルファイル監視 CLI（`c4-zoom ./workspace.dsl`）や VS Code 拡張として展開する道が残されている。
