# 0005: 画面展開状態に基づく動的アンカー射影とエッジロールアップ

- **Status**: Accepted
- **Date**: 2026-11-26

## Context

単一 2D 空間入れ子モデル（[ADR 0001](./0001-spatial-nesting-and-screen-space-lod.md)）では、画面内の各システムがそれぞれ異なる展開状態（あるシステムは L3 まで展開済み、隣のシステムは L1 で閉じたまま）を取り得る。

すべての定義済み関係線（L1〜L3）をそのまま同時描画するとスパゲッティ化して判読不能になる。また、`big-bank-plc.dsl` のように親レベル（`customer -> internetBankingSystem`）と子レベル（`customer -> webApplication` 等）の両方に関係線が併記されるモデルも実在する。

## Decision

**現在の画面展開状態（`detailAlpha`）に基づき、すべての元エッジを可視な最深祖先ノードへ動的に射影・集約する「動的アンカー射影（Dynamic Edge Rollup）」方式を採用する。**

1. 各ノード `u` について、ルートから下って「自身が表示されており、かつ親が展開済み（`detailAlpha >= 0.5`）である最深の祖先ノード」を有効アンカー `anchor(u)` と定義する。
2. 元の関係線 `(s, t)` を `(A, B) = (anchor(s), anchor(t))` へ射影する。
3. **閉じた親内部の自己ループ除去**: `A === B` となる関係線は外部へ漏らさず非表示とする（親が展開された瞬間に内部エッジとして出現する）。
4. **同一ペア集約**: 同一有向ペア `(A, B)` へ射影された複数の関係線（親直接定義と子ロールアップの重複を含む）を 1 本の `DisplayEdge`（件数・プロトコル要約・元 ID 配列付き）へ統合する。
5. **双方向分離**: `(A, B)` と `(B, A)` の双方が存在する場合、ベジェ曲線の制御点を法線方向へオフセットして重なりを防ぐ。
6. **メモ化**: 各ノードの展開状態ハッシュをキーに集約結果をキャッシュし、純粋なパン操作中の再計算を避ける。

## Alternatives Considered

- **定義レベル別の固定フェード切替（自動集約なし）**:
  - L3（Component 間）にしか関係線が書かれていない DSL の場合、L1 俯瞰画面でシステム間の接続線が 1 本も見えなくなってしまうため不採用。
- **通常時は全エッジ非表示（ホバー／選択時のみ表示）**:
  - 地図としての静的な俯瞰理解（「どのシステムとどのシステムが強く繋がっているか」）が損なわれるため不採用。

## Consequences

- **メリット**:
  - DSL 作成者がどの抽象度に関係線を書いても、引きでは幹線・寄りでは詳細線として常に整合した見た目になる。
  - 片側だけ展開された混合ズーム状態でも、`Container -> System` のように破綻なく接続される。
- **トレードオフ・制約**:
  - 集約後のエッジ本数・代表ラベル決定ルール（親直接エッジの説明を優先する等）を明確に定義し、ユニットテストでエッジケースを担保する必要がある。
